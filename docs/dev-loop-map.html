낭비 ① — CI 레인 공백 ✓ 07-09 해소

검증이 전부 "AI가 로컬에서 돌릴 때만" 존재했다. push 뒤 아무도 재검증하지 않으므로, 깨진 커밋이 원격에 올라가도 다음 세션이 시작할 때까지 아무도 몰랐다.

적용.github/workflows/ci.yml 신설 — push·PR 마다 npm ci → db:push → typecheck → test. 07-13 run #1 성공(32초)으로 가동 확인.

낭비 ② — /commit 무게이트 ✓ 07-09 해소

"초록불 없이 커밋 금지"가 ralph-test 스킬 안에만 있었다. 일반 작업은 typecheck·test를 건너뛰고도 커밋이 됐다 — 검증이 절차상 의무가 아니라 선의에 의존했다.

적용/commit 절차 3단계에 검증 게이트 추가(실패 시 커밋 중단, 문서-only 커밋만 예외). 홈·프로젝트 두 사본이 그림자처럼 겹쳐 있어 둘 다 동기화.

병목 ① — 사람이 유일한 직렬 구간

AI 레인(02~05, 07~08열)은 병렬·자동인데, 확인·승인·push(06·08)는 전부 사람을 기다린다. 특히 push가 수동이라 "커밋됐지만 원격엔 없는" 구간이 길어진다.

처방구조는 유지(사람 승인은 안전장치다). 대신 읽기 전용 명령을 허용 목록에 등록해 승인 횟수 자체를 줄이고, push는 세션 끝 1회로 묶는다.

반복 ① — 시행착오가 세션 간 증발

바퀴 간 배움 누적은 ralph-test에만 있다. 일반 개발 루프에서 얻은 교훈 ("lint 쓰지 마라", "Somansa가 TLS 가로챈다")은 사람이 CLAUDE.md에 손으로 적어야만 살아남는다.

처방ralph-test의 📚 규칙("행동을 바꾸는 지식만 한 줄")을 일반화 — 세션 종료 시 배움을 CLAUDE.md·docs에 반영하는 습관/스킬로.

병목 ② — 외부 승인 (사람인 API)

M1 완료 기준(실 데이터 end-to-end)이 외부 승인에 묶여 있다. 루프 개선으로 못 푸는 유일한 병목.

처방기다리는 동안 루프 안 일을 소진: /loop /ralph-test로 테스트 7건 채우기 — 승인 직후 전환(교체 통합)이 하루 안에 끝나게.

해결됨 — 컨텍스트 재로딩 반복

원래 매 세션 STATUS·계약·스킬 목록을 다시 읽는 반복이 있었다. 훅 5종으로 자동 주입해 도구 호출 2→0, 토큰 −14%, 시간 −22%를 실측했다(docs/context.md의 A/B). "반복은 훅으로 없앤다"는 이 프로젝트가 이미 증명한 패턴이다.
